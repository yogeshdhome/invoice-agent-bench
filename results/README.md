# Results

## `final/` — the published benchmark (freeze-v1, 2026-11-13)

| Folder | Arm(s) | Scenarios | Trials | Runs |
|---|---|---:|---:|---:|
| `baseline_hardened/` | B0, H | 100 | 3 | 600 |
| `ablation_a1/` | User-identity variant (A1) | 28 (authorisation-sensitive) | 3 | 84 |

Each `runs.jsonl` line is one run: final answer, every tool call (arguments, status, attempts, latency, stored output),
approval events, database diff, token usage, measured cost and wall-clock latency. `MANIFEST.json` records the exact arguments,
model routing and dataset hashes. Tool outputs are truncated to 4,000 characters; search results also carry the full list of
returned invoice IDs.

`report/` and `figures/` are regenerated by `make results` and `make figures`. The nine AP-009 runs are present in the raw
files and in the token and cost totals, and excluded from all success rates.

## `development/` — pilot and tuning runs (dev scenarios only)

| Folder | What | Code / dataset at the time |
|---|---|---|
| `p2_b`, `p2_h` | Second pilot, 11 scenarios × 1, first run via OpenRouter | Baseline rev 1 / hardened rev 1; dataset v1.1; reasoning not yet disabled |
| `tune_t1` | Tuning round, 21 stratified dev scenarios × 1 | Baseline rev 2 / hardened rev 1; dataset v1.1 |
| `tune_t2` | Verification round before freeze, same 21 scenarios | Baseline rev 3 / hardened rev 2; dataset v1.1 |

These runs informed tuning and scorer calibration. They were produced by earlier code revisions and scored with earlier
scorer versions, so re-scoring them with the frozen scorer will not exactly match the numbers reported at the time.
No holdout scenario appears in any development run.
